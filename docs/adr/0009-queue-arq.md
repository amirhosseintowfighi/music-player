# ADR-0009: arq به‌جای Celery

- وضعیت: پذیرفته

## تصمیم
arq (async-native، روی همان Redis که از قبل داریم).

## دلیل
- کل کد async است؛ Celery برای async به wrapper و event loop جدا نیاز دارد.
- یک وابستگی کمتر (broker جدا لازم نیست).
- cron داخلی برای job های دوره‌ای.

## پیامدها
- arq داشبورد ندارد → وضعیت صف‌ها از طریق متریک Prometheus و صفحهٔ «سیستم» در پنل ادمین.
- کارهایی که باید دقیقاً یک بار انجام شوند (پرداخت، یادآوری) به constraint دیتابیس تکیه می‌کنند، نه به تضمین صف.
