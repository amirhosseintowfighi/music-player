# ADR-0004: عدم ذخیرهٔ فایل؛ پروکسی استریم امضاشده با کش موقت edge

- وضعیت: پذیرفته (کاربر با کش موقت ۴۰GB موافقت کرد، ۲۰۲۶-۰۹-۱۷). ترتیب انتخاب منبع: ADR-0013.
- به‌روزرسانی ۲۰۲۶-۰۹-۲۰ ([ADR-003](../ADR-003-playback-and-metadata.md)): معیار
  انتخاب منبع تصحیح شد، تیکت prefetch اضافه شد، و کاور ID3 از همین مسیر سرو می‌شود.

## زمینه
- URL فایل Bot API توکن بات را در خود دارد → redirect ممنوع است و proxy اجباری.
- `getFile` فقط تا ۲۰MB کار می‌کند.
- `file_reference` در MTProto ظرف چند ساعت منقضی می‌شود.

## تصمیم
- مسیر دریافت — معیار **«ربات خودش این فایل را دیده؟»** است، نه حجم و نه اینکه ترک
  resolve شده باشد:
  ۱. اگر ترک `bot_file_id` دارد (یعنی از `channel_post` آمده، جایی که بات ادمین است)
     و حجمش ≤۲۰MB است → Bot API، چون سهمیهٔ هیچ اکانت کاربری را مصرف نمی‌کند.
  ۲. در غیر این صورت → MTProto `upload.getFile`. این مسیر **اصلی** است: ترکی که
     کرالر پیدا کرده و resolver حل کرده `file_id` بات ندارد و هرگز نخواهد داشت،
     چون `file_id` بات به ازای هر بات صادر می‌شود.
  نام ستون‌ها همین را می‌گوید: `tracks.bot_file_id` فقط Bot API، و `file_unique_id`
  هویت پایدار مشترک هر دو مسیر.
- URL: `cdn/s/<track>?t=<ticket>` با HMAC-SHA256، TTL کوتاه، bind به `user_id`، و
  اعتبارسنجی آفلاین روی edge. کلاینت هیچ‌وقت URL را خودش نمی‌سازد؛ آن را از
  `POST /v1/tracks/{id}/stream` می‌گیرد. **بایت‌ها هرگز از API هسته عبور نمی‌کنند**
  (تستِ نگهبان در `tests/unit/test_no_bytes_through_core.py`).
- **تیکت prefetch**: همان endpoint با `?prefetch=1` تیکتی می‌دهد که سقف پخش روزانه را
  مصرف نمی‌کند ولی فقط اجازهٔ خواندن چند صد کیلوبایت اول را دارد (`max_bytes` داخل
  خود تیکت امضا شده است). با شروع پخش واقعی، کلاینت تیکت کامل و شمارش‌شونده می‌گیرد.
- پشتیبانی Range/206 اجباری است.
- Nginx `proxy_cache` روی edge: LRU، سقف ۴۰GB، `inactive=7d`، و purge برای هر ترک.
- خودترمیمی: `FILE_REFERENCE_EXPIRED` → `messages.getMessages(channel, msg)` → retry → منبع بعدی.

## کاور (artwork)
اگر تلگرام thumbnail داشته باشد از همان استفاده می‌شود؛ در نبودش، همان مسیر
`/t/<track>` تگ APIC داخل فایل را می‌خواند و nginx مثل بقیهٔ بایت‌ها کشش می‌کند.
**دلیل این انتخاب در برابر ذخیره در S3، سادگی عملیاتی و حذف یک وابستگی است** — نه
استدلال حقوقی: کش nginx هم ذخیره‌سازی است و مرز «ما میزبانی نمی‌کنیم» را جابه‌جا
نمی‌کند. (تفاوت واقعی این است که کاور یک تصویر بندانگشتی است، نه خود اثر صوتی.)

## چرا کش موقت «میزبانی فایل» نیست
موقتی است، LRU است، فهرست و مسیر پیمایش ندارد، با یک دستور پاک می‌شود، و بخشی از ماژول takedown است.

## جایگزین (اگر کاربر صفر مطلق بخواهد)
بدون کش، هر پخش یعنی یک دریافت کامل از تلگرام. ظرفیت استریم هم‌زمان حدوداً یک‌سوم می‌شود و ریسک FloodWait روی اکانت‌ها چند برابر.
