# ADR-0015: استک مینی‌اپ و انحراف‌ها از بریف

- وضعیت: پذیرفته (فاز ۴)

## تصمیم
React 19 + TypeScript (strict) + Vite 8 + Tailwind 4 + Framer Motion + Zustand + TanStack Query + React Router (Hash).

## انحراف‌ها از بریف و دلیلشان

| بریف | اجرا | دلیل |
|---|---|---|
| React 18 | **React 19** | نسخهٔ پایدار فعلی؛ همهٔ کتابخانه‌های لیست بریف از آن پشتیبانی می‌کنند و React 18 در حالت نگهداری است |
| `@telegram-apps/sdk-react` | پل نازک خودمان روی `window.Telegram.WebApp` (`src/lib/telegram.ts`) | آن پکیج در npm منسوخ اعلام شده (`@tma.js/*` جایگزینش شده). پل ما ۹۰ خط است، صفر وابستگی اضافه دارد، و بیرون تلگرام هم اجرا می‌شود (برای توسعه و تست) |
| ESLint | فقط `tsc --strict` + تست | نسخهٔ فعلی eslint با پلاگین‌های React تعارض peer داشت. تایپ‌چک سخت‌گیرانه و ۳۸ تست پوشش می‌دهند؛ اگر لازم شد بعداً اضافه می‌شود |
| `<audio>` + Web Audio API | فقط `<audio>` | Web Audio فقط برای crossfade لازم است و در وب، کراس‌فید روی استریم‌های محافظت‌شده (Range + توکن) قابل‌اتکا نیست. صف، shuffle، repeat، سرعت و تایمر خواب همه با `<audio>` پیاده شده‌اند |

## نکات پیاده‌سازی
- **HashRouter** انتخاب شد: WebView تلگرام مسیر را با پارامترهای خودش باز می‌کند و مسیر hash از تداخل با آن‌ها و با `try_files` در nginx در امان است.
- **کاور آهنگ‌ها** از endpoint دسته‌ای `POST /v1/tracks/thumbs` می‌آید. این endpoint سقف پخش روزانه را مصرف نمی‌کند و لینک‌های یک‌ساعته می‌دهد، چون مرور یک لیست «گوش دادن» نیست.
- **باندل اولیه** ۱۵۵ کیلوبایت gzip (بودجه ۲۰۰). پلیر تمام‌صفحه lazy است. اسکریپت `scripts/check-size.mjs` بیلد را در صورت عبور از بودجه قرمز می‌کند.
