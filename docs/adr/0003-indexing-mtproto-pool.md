# ADR-0003: ایندکس با pool اکانت MTProto؛ کانال به‌عنوان موجودیت سراسری

- وضعیت: **جایگزین‌شده** با [ADR-002](../ADR-002-indexing-strategy.md) (۲۰۲۶-۰۹-۲۰)
- آنچه از این سند زنده مانده: «کانال یک موجودیت سراسری است»، مسیر B (بات ادمین)،
  ذخیرهٔ cursor بعد از هر گام، و ممنوعیت retry فوری روی FloodWait. آنچه حذف شد:
  pool چنداکانته، sharding کانال روی اکانت و backfill با `messages.getHistory`.

## تصمیم
- مسیر A (عمومی): Telethon با pool ۲–۵ اکانت، sharding چسبنده `channel → account`.
- مسیر B (خصوصی): بات ادمین کانال می‌شود؛ فقط پیام‌های جدید خوانده می‌شوند (Bot API تاریخچه نمی‌دهد و راه دور زدنی ندارد).
- هر کانال یک بار برای کل پلتفرم ایندکس می‌شود؛ `user_channels` فقط رابطهٔ subscribe است.
- backfill همیشه در صف انجام می‌شود و cursor بعد از هر batch ذخیره می‌شود.
- FloodWait: `sleep(seconds + jitter)` و رفتن اکانت به حالت `cooling`. retry فوری ممنوع است.

## پیامدها
- سقف ۵۰۰ کانال برای هر اکانت → با ۵ اکانت، سقف ۲۵۰۰ کانال. این متریک ظرفیت در داشبورد نمایش داده می‌شود.
- چون shard چسبنده است، بن‌شدن یک اکانت یعنی کانال‌هایش باید تدریجی به بقیه منتقل شوند.
- session ها با AES-GCM رمز می‌شوند؛ کلید فقط در env روی edge است.
